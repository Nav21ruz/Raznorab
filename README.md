# Стройбиржа

Биржа для стройки и разовых подработок. Работает в двух видах из одного кода:

- **Telegram Mini App** — вход автоматический, по Telegram-аккаунту.
- **Обычный сайт на своём домене** — вход по email и паролю, ставится на телефон как приложение (PWA).

Приложение не зависит от доступности Telegram: в веб-режиме к `telegram.org` не делается ни одного запроса.

- **Заказчик ↔ Строитель** — как Тиндер: заказчик публикует заказ, строители свайпают ленту заказов (вправо — отклик, влево — пропуск). Заказчик просматривает отклики и подтверждает мэтч — открывается чат.
- **Разнорабочие** — отдельный, более простой раздел: заказчик публикует разовую задачу, разнорабочие просто откликаются в ленте без свайпов, заказчик выбирает исполнителя.
- Чат между мэтчами в реальном времени (Supabase Realtime).

Плюс отдельный, не связанный с биржей инструмент — **Журнал объекта** (`/journal`) для прораба: дневник строительного объекта с фото, статистикой и PDF-отчётами.

### Модерация

- **Фильтр цензуры** — список стоп-слов (`banned_words`) хранится в БД и маскируется прямо в Postgres-триггерах при вставке/обновлении заказов, задач, сообщений чата и профиля строителя. Это нельзя обойти в обход интерфейса. На клиенте та же проверка даёт мгновенную подсказку до отправки. Список изначально пуст — админ наполняет его сам через панель под свою политику модерации.
- **Жалобы** — на заказ, задачу разнорабочих или пользователя (кнопка с флажком на карточках в ленте/у отклика, в чате, на странице задачи).
- **Админ-панель** (`/admin`, не в общем доступе) — дашборд со сводкой, очередь жалоб с действиями (рассмотрено/отклонено/бан автора), поиск и бан/разбан пользователей, управление стоп-словами.

## Стек

React 19 + TypeScript + Vite + Tailwind CSS 4, React Router, TanStack Query, Supabase (Postgres + Auth + Storage + Realtime), framer-motion (свайп-механика), `@twa-dev/sdk` (Telegram Web App).

## Запуск

```bash
npm install
npm run dev
```

Без переменных окружения (см. ниже) приложение автоматически работает в демо-режиме: данные хранятся только в localStorage браузера, без реального бэкенда — этого достаточно, чтобы открыть и попробовать все сценарии локально.

## Подключение реального Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. Выполните по порядку в SQL Editor: `supabase/marketplace_schema.sql`, затем `supabase/moderation_schema.sql` (админка, баны, жалобы, фильтр цензуры). При необходимости также `supabase/schema.sql` (журнал объекта).
3. Создайте публичный Storage-бакет `marketplace-photos` (для журнала — `entry-photos`).
4. Скопируйте `.env.example` в `.env` и укажите `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`.
5. **Назначьте первого админа** — самостоятельной регистрации админов в приложении нет (это осознанно, чтобы никто не мог сам себе выдать права). Откройте приложение один раз как обычный пользователь, найдите свою запись в таблице `profiles` (по `telegram_id` или `telegram_username`) и выполните в SQL Editor:
   ```sql
   insert into admins (profile_id) values ('<ваш profiles.id>');
   ```
   После этого `/admin` станет доступен именно вам — маршрут никак не привязан к ролям заказчика/строителя/разнорабочего и не отображается в обычной навигации.

Аутентификация в мини-аппе — анонимная сессия Supabase, привязанная к профилю по `telegram_id`. Для продакшена рекомендуется добавить серверную проверку Telegram `initData` (например, через Supabase Edge Function), чтобы исключить подмену telegram-профиля.

## Публикация на своём домене

По умолчанию сборка рассчитана на корень домена:

```bash
npm run build      # результат в dist/, залить на любой статический хостинг
```

Подойдёт что угодно, раздающее статику: Vercel, Netlify, Cloudflare Pages, обычный nginx на VPS.

Одно обязательное условие: это SPA, поэтому сервер должен отдавать `index.html` на любой неизвестный путь,
иначе прямые ссылки (`/orders`, `/chats/...`) будут давать 404. Для nginx:

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

Vercel/Netlify/Cloudflare Pages делают это сами.

### Установка как приложение (PWA)

Собранный сайт — полноценное PWA: манифест, иконки и service worker уже настроены.
На телефоне в меню браузера появится «Установить приложение» / «На экран «Домой»» — оно
запускается в отдельном окне без адресной строки и с обычной иконкой.

Отдельного приложения в магазинах для этого не нужно. Если позже понадобятся пуш-уведомления
или публикация в сторах — тот же код оборачивается в нативную сборку через
[Capacitor](https://capacitorjs.com), переписывать ничего не придётся.

### GitHub Pages

Сайт раздаётся из подпапки, поэтому нужен базовый путь — он уже прописан в
`.github/workflows/deploy.yml` (`VITE_BASE_PATH=/raznorab/`). При переезде на свой домен
просто уберите эту переменную.

## Подключение в Telegram

Задайте URL мини-аппа в [@BotFather](https://t.me/BotFather) (`/newapp` или `/setmenubutton`).

Внутри Telegram приложение узнаёт себя по параметрам запуска и подгружает Telegram SDK
динамически; в обычном браузере SDK не загружается вообще, поэтому недоступность
`telegram.org` никак не влияет на веб-версию.

## Вход

| Где открыто | Как входит пользователь |
|---|---|
| Внутри Telegram | Автоматически, профиль привязан к `telegram_id` |
| Обычный браузер | Email + пароль (регистрация внутри приложения) |

Вход по СМС пока не подключён — это осознанно, чтобы запуститься без затрат на СМС-провайдера.
Когда понадобится, добавляется как ещё один способ входа Supabase (`signInWithOtp`) рядом
с email, без переделки остального кода: профиль и все данные привязаны к `profiles.id`,
а не к способу авторизации.
